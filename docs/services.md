# Microservices

## 1. Identity Service

Назначение:
Управление пользователями и их аутентификацией.

Ответственность:
- Регистрация пользователей.
- Хранение профилей.
- Авторизация.
- Генерация и проверка JWT.
- Управление ролями и правами доступа.

Хранилище:
PostgreSQL.

Identity Service не управляет финансовыми счетами и балансами.

## 2. Ledger Service

Назначение:
Центральный финансовый компонент системы и источник истины
о движении денежных средств.

Ответственность:
- Создание финансовых счетов.
- Хранение балансов.
- Создание финансовых проводок.
- Double-entry bookkeeping.
- Проверка финансовых ограничений.
- Симулированное пополнение.
- Учет движения средств.
- Обеспечение атомарности финансовых операций.

Хранилище:
PostgreSQL.

Ledger Service — единственный сервис, который непосредственно
изменяет финансовое состояние счетов.

Финансовые проводки неизменяемы.

## 3. Transfer Service

Назначение:
Управление жизненным циклом переводов между пользователями.

Ответственность:
- Создание переводов.
- Проверка бизнес-параметров перевода.
- Идемпотентность запросов.
- Управление статусами переводов.
- Отмена и возврат переводов.
- Взаимодействие с Ledger Service.
- Обработка результатов финансовых операций.

Хранилище:
PostgreSQL.

Transfer Service не изменяет балансы напрямую.

## 4. Scheduler Service

Назначение:
Управление отложенными и регулярными операциями.

Ответственность:
- Создание расписаний.
- Управление разовыми отложенными переводами.
- Управление регулярными переводами.
- Запуск запланированных операций.
- Отмена расписаний.
- Обработка ошибок выполнения.
- Хранение истории запусков.

Технология:
Quartz Scheduler с JDBC JobStore.

Хранилище:
PostgreSQL.

Scheduler Service не проводит финансовые операции самостоятельно.
Он инициирует выполнение переводов через Transfer Service.

## 5. Notification Service (будущий сервис)

Назначение:
Обработка и хранение пользовательских уведомлений.

Ответственность:
- Получение событий из Kafka.
- Формирование уведомлений.
- Хранение истории уведомлений.
- Учет попыток доставки.

Хранилище:
MongoDB.

Notification Service не участвует в изменении финансовых балансов.

## 6. API Gateway (будущий компонент)

Назначение:
Единая точка входа для внешних клиентов.

Ответственность:
- Маршрутизация запросов.
- Проверка JWT.
- CORS.
- Базовое ограничение частоты запросов.

Gateway не содержит финансовой бизнес-логики.
