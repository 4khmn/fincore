# Architecture

## Общая архитектура

FinCore использует микросервисную архитектуру.

Каждый сервис является отдельным Spring Boot-приложением
и владеет собственным хранилищем данных.

Сервисы не обращаются напрямую к таблицам других сервисов.

## Взаимодействие

### REST

Используется для внешних HTTP-запросов от клиента.

В будущем внешние запросы будут проходить через API Gateway.

### gRPC

Используется для синхронного взаимодействия между сервисами.

Основной сценарий:
Transfer Service -> Ledger Service.

### Apache Kafka

Используется для асинхронного обмена событиями.

Примеры событий:
- AccountCredited
- MoneyTransferred
- TransferFailed
- ScheduledTransferExecuted

Для надежной публикации событий планируется использовать
Transactional Outbox.

Для безопасной обработки повторных сообщений —
идемпотентность и Inbox.

## Хранение данных

- PostgreSQL — основное реляционное хранилище.
- MongoDB — хранение документов и истории уведомлений.
- Redis — вспомогательное быстрое хранилище, например для кеша.

Каждый сервис владеет своими данными.

## Надежность

Система не предполагает глобальную транзакцию между
микросервисами.

Для обработки сбоев используются:
- Идемпотентность.
- Уникальные ограничения БД.
- Transactional Outbox.
- Inbox.
- Повторные попытки.
- Таймауты.
- Устойчивые статусы операций.
- Восстановление после перезапуска.

Exactly-once для Kafka и планировщика не предполагается.

## Развертывание

Локальная разработка:
Docker Compose.

Оркестрация:
Kubernetes.

Каждый сервис должен иметь собственный Docker-образ
и возможность независимого развертывания.
