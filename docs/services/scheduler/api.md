# Scheduler Service — API

## Назначение

Scheduler Service управляет отложенными и регулярными переводами.

Для управления временем запуска используется Quartz Scheduler
с JDBC JobStore.

Scheduler Service не изменяет балансы и не проводит финансовые
операции самостоятельно.

Для выполнения перевода он отправляет команду в Kafka,
которую обрабатывает Transfer Service.

Base path: /api/v1

## 1. Создание запланированного перевода

POST /schedules

Авторизация: обязательна.

Request для разового перевода:

{
"fromAccountId": "account-uuid-1",
"toAccountId": "account-uuid-2",
"amount": "5000.00",
"scheduleType": "ONCE",
"executeAt": "2026-12-01T12:00:00+03:00"
}

Request для регулярного перевода:

{
"fromAccountId": "account-uuid-1",
"toAccountId": "account-uuid-2",
"amount": "1000.00",
"scheduleType": "RECURRING",
"cronExpression": "0 0 12 1 * ?",
"timeZone": "Europe/Moscow"
}

Response: 201 Created

{
"id": "schedule-uuid",
"scheduleType": "ONCE",
"status": "ACTIVE",
"nextExecutionAt": "2026-12-01T12:00:00+03:00",
"createdAt": "2026-11-18T10:00:00Z"
}

Ошибки:
- 400 — некорректные параметры расписания.
- 401 — пользователь не авторизован.
- 403 — пользователь не владеет счётом отправителя.
- 404 — счёт не найден.
- 409 — расписание не может быть создано.

Правила:
- Отправитель должен владеть счётом списания.
- Счета должны иметь одинаковую валюту.
- Сумма должна быть больше нуля.
- Валюта и сумма сохраняются в расписании.
- Время должно содержать часовой пояс или быть однозначно
  интерпретируемым согласно правилам API.
- Создание расписания ещё не означает успешное проведение перевода.

## 2. Получение списка расписаний

GET /schedules

Авторизация: обязательна.

Query parameters:
- page — номер страницы.
- size — размер страницы.
- status — необязательный фильтр.
- scheduleType — ONCE или RECURRING.

Response: 200 OK

{
"content": [
{
"id": "schedule-uuid",
"scheduleType": "RECURRING",
"status": "ACTIVE",
"amount": "1000.00",
"currency": "RUB",
"nextExecutionAt": "2026-12-01T12:00:00+03:00"
}
],
"page": 0,
"size": 20,
"totalElements": 1,
"totalPages": 1
}

Возвращаются только расписания текущего пользователя.

## 3. Получение расписания

GET /schedules/{scheduleId}

Авторизация: обязательна.

Response: 200 OK

{
"id": "schedule-uuid",
"fromAccountId": "account-uuid-1",
"toAccountId": "account-uuid-2",
"amount": "1000.00",
"currency": "RUB",
"scheduleType": "RECURRING",
"status": "ACTIVE",
"cronExpression": "0 0 12 1 * ?",
"timeZone": "Europe/Moscow",
"nextExecutionAt": "2026-12-01T12:00:00+03:00"
}

## 4. Изменение расписания

PATCH /schedules/{scheduleId}

Авторизация: обязательна.

В первой версии можно изменять только активное расписание.

Request:

{
"amount": "1500.00"
}

Response: 200 OK

{
"id": "schedule-uuid",
"amount": "1500.00",
"status": "ACTIVE"
}

Изменение уже выполняющегося запуска не должно менять его параметры.
Новые параметры применяются к будущим запускам.

## 5. Отмена расписания

DELETE /schedules/{scheduleId}

Авторизация: обязательна.

Response: 204 No Content

Правила:
- Отменяется расписание, а не уже завершённый перевод.
- Новые запуски больше не должны создаваться.
- Если запуск уже начался, его состояние проверяется отдельно.
- Отмена не должна автоматически отменять уже проведённую
  финансовую операцию.

## 6. История выполнений

GET /schedules/{scheduleId}/executions

Авторизация: обязательна.

Response: 200 OK

{
"content": [
{
"id": "execution-uuid",
"scheduledFor": "2026-12-01T12:00:00+03:00",
"status": "COMPLETED",
"transferId": "transfer-uuid",
"executedAt": "2026-12-01T12:00:02+03:00"
}
],
"page": 0,
"size": 20,
"totalElements": 1,
"totalPages": 1
}

## Типы расписаний

ONCE:
- Один запуск в конкретный момент времени.
- После завершения расписание становится COMPLETED.

RECURRING:
- Повторные запуски по cron-выражению.
- После каждого запуска рассчитывается следующий запуск.
- Расписание остаётся ACTIVE, пока пользователь его не отменит
  или оно не будет остановлено по бизнес-правилам.

## Статусы расписания

- ACTIVE — расписание активно.
- PAUSED — расписание временно приостановлено.
- COMPLETED — разовое расписание выполнено.
- CANCELLED — пользователь отменил расписание.
- FAILED — расписание остановлено из-за критической ошибки.

## Статусы выполнения

- PENDING — ожидает запуска.
- PROCESSING — команда отправлена на выполнение.
- COMPLETED — перевод успешно завершён.
- FAILED — перевод завершился ошибкой.
- RETRYING — запланирована повторная попытка.

## Надёжность

- Quartz отвечает за запуск задач по расписанию.
- Каждое конкретное выполнение получает уникальный executionId.
- Команды передаются через Kafka.
- Публикация команды должна использовать Transactional Outbox.
- Повторная доставка команды не должна создавать повторный перевод.
- Transfer Service обеспечивает идемпотентность выполнения.
- Quartz не гарантирует однократный финансовый эффект.
