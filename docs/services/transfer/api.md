# Transfer Service — API

## Назначение

Transfer Service управляет жизненным циклом переводов между
пользователями.

Он принимает запросы на перевод, проверяет бизнес-правила,
обеспечивает идемпотентность и взаимодействует с Ledger Service.

Transfer Service не изменяет балансы напрямую.

Base path: /api/v1

## 1. Создание перевода

POST /transfers

Авторизация: обязательна.

Headers:

Authorization: Bearer <JWT>
Idempotency-Key: unique-request-key

Request:

{
"fromAccountId": "account-uuid-1",
"toAccountId": "account-uuid-2",
"amount": "3000.00"
}

Response: 201 Created

{
"id": "transfer-uuid",
"fromAccountId": "account-uuid-1",
"toAccountId": "account-uuid-2",
"amount": "3000.00",
"currency": "RUB",
"status": "COMPLETED",
"createdAt": "2026-11-18T10:00:00Z"
}

Возможен также ответ 202 Accepted, если перевод ещё обрабатывается.

Ошибки:
- 400 — некорректная сумма или параметры.
- 401 — пользователь не авторизован.
- 403 — пользователь не владеет счётом отправителя.
- 404 — счёт не найден.
- 409 — конфликт idempotency key или несовместимые валюты.
- 422 — недостаточно средств или операция невозможна.

Правила:
- Сумма должна быть больше нуля.
- Отправитель должен владеть счётом списания.
- Получатель должен владеть счётом зачисления.
- Счета должны иметь одинаковую валюту.
- Перевод между собственными счетами разрешён.
- Перевод между разными валютами запрещён.
- Финансовое проведение выполняет Ledger Service.

## 2. Получение списка переводов

GET /transfers

Авторизация: обязательна.

Query parameters:
- page — номер страницы, начиная с 0.
- size — размер страницы.
- status — необязательный фильтр по статусу.
- fromDate — начало периода.
- toDate — конец периода.

Response: 200 OK

{
"content": [
{
"id": "transfer-uuid",
"fromAccountId": "account-uuid-1",
"toAccountId": "account-uuid-2",
"amount": "3000.00",
"currency": "RUB",
"status": "COMPLETED",
"createdAt": "2026-11-18T10:00:00Z"
}
],
"page": 0,
"size": 20,
"totalElements": 1,
"totalPages": 1
}

Возвращаются только переводы, в которых текущий пользователь
является отправителем или получателем.

## 3. Получение перевода

GET /transfers/{transferId}

Авторизация: обязательна.

Response: 200 OK

{
"id": "transfer-uuid",
"fromAccountId": "account-uuid-1",
"toAccountId": "account-uuid-2",
"amount": "3000.00",
"currency": "RUB",
"status": "COMPLETED",
"createdAt": "2026-11-18T10:00:00Z",
"updatedAt": "2026-11-18T10:00:01Z"
}

Ошибки:
- 401 — пользователь не авторизован.
- 404 — перевод не найден или пользователь не имеет доступа.

## 4. Отмена перевода

POST /transfers/{transferId}/cancel

Авторизация: обязательна.

В первой версии отмена доступна только для перевода,
который ещё не был финансово проведён.

Response: 200 OK

{
"id": "transfer-uuid",
"status": "CANCELLED"
}

Ошибки:
- 401 — пользователь не авторизован.
- 404 — перевод не найден.
- 409 — перевод уже завершён или его нельзя отменить.

Примечание:
Возврат уже проведённого перевода — отдельная финансовая операция.
Он не должен удалять или изменять исходные проводки.
Возвраты будут добавлены отдельным этапом.

## Статусы перевода

- PENDING — перевод зарегистрирован, ожидает обработки.
- PROCESSING — выполняется финансовая операция.
- COMPLETED — деньги успешно переведены.
- FAILED — операция завершилась ошибкой.
- CANCELLED — перевод отменён до проведения.

## Идемпотентность

Каждый запрос на создание перевода должен содержать
Idempotency-Key.

Ключ уникален в пределах пользователя.

Повторный запрос с тем же ключом и теми же параметрами
должен вернуть результат первоначального запроса.

Повторный запрос с тем же ключом, но другими параметрами,
должен завершаться конфликтом.

Transfer Service передаёт в Ledger устойчивый operationId,
связанный с конкретным переводом.

При таймауте gRPC нельзя считать операцию неуспешной:
необходимо проверить её состояние в Ledger или безопасно
повторить запрос с тем же operationId.
