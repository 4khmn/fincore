# Requirements

## 1. Пользователи

- Регистрация пользователей.
- Авторизация через JWT.
- У каждого пользователя могут быть собственные финансовые счета.

## 2. Счета и валюты

- Поддержка нескольких валют: RUB, USD, EUR.
- Один счёт хранит средства только в одной валюте.
- Конвертация валют не входит в первоначальный объём проекта.
- Баланс счёта не может быть отрицательным.

## 3. Пополнение

- Пользователь может пополнить счёт виртуальными средствами.
- Пополнение является симуляцией, а не реальным банковским платежом.
- Каждое пополнение должно иметь уникальный идентификатор операции.

## 4. Переводы

- Перевод средств между пользователями.
- Проверка достаточности средств.
- Поддержка идемпотентности.
- Сохранение истории операций.
- Поддержка отмены и возврата через компенсирующие операции.
- Перевод не должен повторно списывать средства при повторном запросе.

## 5. Планировщик

- Создание разового отложенного перевода.
- Создание регулярного перевода.
- Отмена запланированных операций.
- История запусков и попыток выполнения.
- Обработка ошибок и повторные попытки.

## 6. Резервирование

Полноценное резервирование средств (holds) не входит в первую
версию. Будет реализовано отдельным этапом.

## 7. Уведомления

- Уведомление о поступлении средств.
- Уведомление об отправке перевода.
- Уведомление о неудачном запланированном переводе.

## 8. Нефункциональные требования

- Согласованность финансовых данных.
- Идемпотентность финансовых операций.
- Устойчивость к повторной доставке сообщений.
- Обработка конкурентных запросов.
- Восстановление после перезапуска сервисов.
- Независимое развертывание микросервисов.
- Мониторинг и логирование.
- Контейнеризация и оркестрация через Kubernetes.
